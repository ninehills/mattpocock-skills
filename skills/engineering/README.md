# 工程

我日常代码工作中使用的技能。

- **[diagnose](./diagnose/SKILL.md)** — 针对复杂 Bug 和性能退化的严谨诊断循环：复现 → 最小化 → 假设 → 插桩 → 修复 → 回归测试。
- **[grill-with-docs](./grill-with-docs/SKILL.md)** — 审查会议，针对现有领域模型挑战你的计划，打磨术语，并在决策明确时内联更新 `CONTEXT.md` 和 ADR。
- **[triage](./triage/SKILL.md)** — 通过分诊角色状态机对问题进行分诊。
- **[improve-codebase-architecture](./improve-codebase-architecture/SKILL.md)** — 在代码库中发现深化机会，基于 `CONTEXT.md` 中的领域语言和 `docs/adr/` 中的决策。
- **[setup-matt-pocock-skills](./setup-matt-pocock-skills/SKILL.md)** — 搭建每个仓库的配置（问题跟踪器、分诊标签词汇、领域文档布局），供其他工程技能使用。
- **[tdd](./tdd/SKILL.md)** — 测试驱动开发，红-绿-重构循环。逐个垂直切片构建功能或修复 Bug。
- **[to-issues](./to-issues/SKILL.md)** — 使用垂直切片将任何计划、规格或 PRD 拆分为可独立领取的 GitHub Issue。
- **[to-prd](./to-prd/SKILL.md)** — 将当前对话上下文转化为 PRD 并作为 GitHub Issue 提交。
- **[zoom-out](./zoom-out/SKILL.md)** — 告诉代理拉远视角，对不熟悉的代码段给出更广泛的上下文或更高层次的视角。
- **[prototype](./prototype/SKILL.md)** — 构建一次性原型来充实设计——可以是用于状态/业务逻辑问题的可运行终端应用，也可以是从单个路由切换的多种截然不同的 UI 方案。
