# 逻辑原型

一个小型交互式终端应用，让用户手动驱动状态模型。当问题关于**业务逻辑、状态转换或数据形状**时使用——那种在纸上看起来合理但只有在你用真实用例推过之后才感觉不对的东西。

## 何时这是正确的形状

- "我不确定这个状态机器是否处理了 X 然后 Y 的边界情况。"
- "这个数据模型是否真的让我能表示……的情况？"
- "我想在写 API 之前感受一下它应该是什么样的。"
- 任何用户想要**按按钮看状态变化**的时候。

如果问题是"这个应该长什么样"——错误的分支。使用 [UI.md](UI.md)。

## 流程

### 1. 说明问题

在写代码之前，写下你正在原型化的状态模型和问题。一段话，在原型的 README 或文件顶部的注释中。回答错误问题的逻辑原型是纯粹的浪费——让问题明确，以便稍后可以检查，无论用户现在在看还是之后回来。

### 2. 选择语言

使用宿主项目使用的语言。如果项目没有明显的运行时（例如文档仓库），询问。

匹配项目现有的工具约定——不要仅为原型添加新的包管理器或运行时。

### 3. 将逻辑隔离在可移植模块中

将实际逻辑——回答问题的部分——放在一个小的、纯净的接口后面，以后可以提取并放入真正的代码库。围绕它的 TUI 是可丢弃的；逻辑模块不应该是。

正确的形状取决于问题：

- **纯 reducer** — `(state, action) => state`。当操作是离散事件且状态是单个值时很好。
- **状态机** — 明确的状态和转换。当"哪些操作现在甚至是合法的"是问题的一部分时很好。
- **一组小型纯函数**，操作普通数据类型。当没有隐式当前状态——只有转换时很好。
- **具有清晰方法表面的类或模块**，当逻辑真正拥有持续的内部状态时。

选择最适合所问问题的形状，*而不是*最容易连接到 TUI 的。保持纯净：无 I/O，无终端代码，无用于控制流的 `console.log`。TUI 导入它并调用它；没有东西反向流动。

这就是使原型在其自身生命周期之外仍然有用的原因。当问题被回答后，经过验证的 reducer/机器/函数集可以提取到真正的模块中——TUI 外壳被删除。

### 4. 构建暴露状态的最小 TUI

将其构建为**轻量级 TUI** — 在每个 tick，清屏（`console.clear()` / `print("\033[2J\033[H")` / 等效）并重新渲染整个帧。用户应该始终看到一个稳定的视图，而不是不断增长的回滚。

每帧有两部分，按此顺序：

1. **当前状态**，漂亮打印且差异友好（每行一个字段，或格式化的 JSON）。对字段名或节标题使用**加粗**，对不太重要的上下文（时间戳、ID、派生值）使用**暗淡**。原生 ANSI 转义码即可——`\x1b[1m` 加粗，`\x1b[2m` 暗淡，`\x1b[0m` 重置。除非项目中已有，否则不需要引入样式库。
2. **键盘快捷键**，列在底部：`[a] 添加用户  [d] 删除用户  [t] 时钟滴答  [q] 退出`。加粗按键，暗淡描述，或反过来——以清晰易读为准。

行为：

1. **初始化状态** — 单个内存对象/结构。启动时渲染第一帧。
2. **读取一个按键（或一行）**，分派到改变状态的处理器。
3. **在每个操作后重新渲染**完整帧——不要追加，替换。
4. **循环直到退出。**

整个帧应该在一屏内显示。

### 5. 使其可通过一个命令运行

向项目现有的任务运行器（`package.json` scripts、`Makefile`、`justfile`、`pyproject.toml`）添加脚本。用户应该运行 `pnpm run <prototype-name>` 或等效命令——永远不需要记住路径。

如果宿主项目没有任务运行器，只需将命令放在原型 README 的顶部。

### 6. 交付

给用户运行命令。他们自己驱动；有趣的时刻是他们说"等等，那不应该可能"或"嗯，我以为 X 会不同"——那些是*想法*中的 Bug，而这正是全部意义。如果他们想添加新操作，就添加。原型会演进。

### 7. 捕获答案

当原型完成了它的工作，问题的答案是唯一值得保留的。如果用户在场，问他们学到了什么。如果不在，在原型旁边留一个 `NOTES.md`，以便答案可以在原型被删除之前填入（或如果你观看了会话，由你填入）。

## 反模式

- **不要添加测试。** 需要测试的原型不再是原型。
- **不要连接到真实数据库。** 使用内存存储，除非问题专门关于持久化。
- **不要泛化。** 没有"如果我们以后想支持 X 呢"。原型回答一个问题。
- **不要模糊逻辑和 TUI。** 如果 reducer/状态机引用了 `console.log`、提示或终端转义码，它就不再可移植。保持 TUI 作为纯模块之上的薄壳。
- **不要将 TUI 外壳推入生产。** 外壳是为了从终端手动驱动而优化的。它背后的逻辑模块才是值得保留的部分。
