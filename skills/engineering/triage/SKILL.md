# 分诊

通过一个小的分诊角色状态机在项目问题跟踪器上移动 Issue。

分诊期间发布到问题跟踪器的每个评论或 Issue **必须**以此免责声明开头：

```
> *此内容由 AI 在分诊期间生成。*
```

## 参考文档

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — 如何编写持久的代理简报
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — `.out-of-scope/` 知识库如何运作

## 角色

两个**类别**角色：

- `bug` — 某个功能坏了
- `enhancement` — 新功能或改进

五个**状态**角色：

- `needs-triage` — 维护者需要评估
- `needs-info` — 等待报告者提供更多信息
- `ready-for-agent` — 完全指定，准备好由离线代理领取
- `ready-for-human` — 需要人工实现
- `wontfix` — 不会被处理

每个已分诊的 Issue 应恰好携带一个类别角色和一个状态角色。如果状态角色冲突，标记出来并在做任何其他事之前询问维护者。

这些是规范角色名称——问题跟踪器中使用的实际标签字符串可能不同。映射应该已经提供给你——如果没有，运行 `/setup-matt-pocock-skills`。

状态转换：未标记的 Issue 通常先到 `needs-triage`；从那里移动到 `needs-info`、`ready-for-agent`、`ready-for-human` 或 `wontfix`。`needs-info` 在报告者回复后返回 `needs-triage`。维护者可以随时覆盖——标记看起来不寻常的转换并在继续之前询问。

## 调用

维护者调用 `/triage` 并用自然语言描述他们想要什么。解释请求并行动。示例：

- "给我看看需要我关注的"
- "看看 #42"
- "将 #42 移到 ready-for-agent"
- "什么准备好让代理领取了？"

## 显示需要关注的内容

查询问题跟踪器并展示三个桶，最旧的优先：

1. **未标记** — 从未分诊。
2. **`needs-triage`** — 评估进行中。
3. **`needs-info` 且报告者在上次分诊笔记后有活动** — 需要重新评估。

显示计数和每个 Issue 的一行摘要。让维护者选择。

## 分诊特定 Issue

1. **收集上下文。** 读取完整的 Issue（正文、评论、标签、报告者、日期）。解析任何先前的分诊笔记以免重复询问已解决的问题。使用项目的领域词汇表探索代码库，尊重该区域的 ADR。读取 `.out-of-scope/*.md` 并提出来与此 Issue 相似的任何先前拒绝。

2. **建议。** 告诉维护者你的类别和状态建议及理由，加上与 Issue 相关的代码库简要摘要。等待指示。

3. **复现（仅 Bug）。** 在任何审查之前，尝试复现：读取报告者的步骤，跟踪相关代码，运行测试或命令。报告发生了什么——成功复现及代码路径、复现失败、或细节不足（强 `needs-info` 信号）。确认的复现会产生更强的代理简报。

4. **审查（如需要）。** 如果 Issue 需要充实，运行 `/grill-with-docs` 会话。

5. **应用结果：**
   - `ready-for-agent` — 发布代理简报评论（[AGENT-BRIEF.md](AGENT-BRIEF.md)）。
   - `ready-for-human` — 与代理简报相同的结构，但注明为什么不能委托（判断、外部访问、设计决策、手动测试）。
   - `needs-info` — 发布分诊笔记（模板见下）。
   - `wontfix`（bug）— 礼貌解释，然后关闭。
   - `wontfix`（enhancement）— 写入 `.out-of-scope/`，从评论中链接到它，然后关闭（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage` — 应用角色。如果有部分进展可选评论。

## 快速状态覆盖

如果维护者说"把 #42 移到 ready-for-agent"，信任他们并直接应用角色。确认你即将做什么（角色变更、评论、关闭），然后行动。跳过审查。如果在没有审查会话的情况下移到 `ready-for-agent`，询问他们是否想写代理简报。

## Needs-info 模板

```markdown
## 分诊笔记

**目前确定的内容：**

- 要点 1
- 要点 2

**我们仍然需要你（@reporter）提供：**

- 问题 1
- 问题 2
```

在"目前确定的内容"下捕获审查期间解决的所有内容，以免工作丢失。问题必须具体且可操作，而不是"请提供更多信息"。

## 恢复先前会话

如果 Issue 上有先前的分诊笔记，读取它们，检查报告者是否回答了任何未决问题，并在继续之前展示更新的情况。不要重复询问已解决的问题。
